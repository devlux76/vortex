Write `lib/vortex/router/policy.ex` defining `Vortex.Router.Policy` so that `mix test test/t7_test.exs` passes. Do not edit the test file.

The policy decides when an agent's wake adapter may be started for unread mail. It is a pure state machine: no processes, no clock, no I/O. The caller supplies the time and carries out the actions.

```elixir
Policy.new(opts)               # => a %Policy{} struct with at least a :boot field
Policy.step(policy, event, now_ms)   # => {policy, actions}
Policy.starts(policy)          # => %{room => [start_time_ms, ...]} newest first, for the caller to persist
```

Options and their defaults: `max_per_hour: 4`, `min_interval_ms: 30_000`, `owner_quiet_ms: 30_000`, `max_failures: 3`, `starts: %{}` (from an earlier `starts/1`), and `boot:` the prefix of ring ids, a random string unless given.

## Events

* `{:state, %{waiters: n, running: id | nil, rooms: [%{room: key, unread: n, oldest: cursor}]}}`: a full snapshot of unread mail, replacing what was known. `waiters` is how many agents are blocked waiting for mail. `running` is the ring the service says is running.
* `:acted`: the owner read or acknowledged mail.
* `{:started, id}`: the service started the adapter for ring `id`.
* `{:refused, id}`: the service did not start it.
* `{:exited, id, code}`: the adapter for ring `id` exited.
* `:offline`: the service disconnected.
* `:tick`: a wake-up the policy asked for has arrived.

## Actions

A step returns at most one action.

* `{:ring, id, room, unread}`: ask the service to start its adapter. `id` is `"<boot>-<n>"` with `n` counting from 1. `unread` is the total across all rooms.
* `{:wake_at, ms}`: ask for a `:tick` at this time. A step that returns no action wants no wake-up.

## Rules

After every event the policy decides again.

1. It rings only when there is unread mail, no waiter, no ring pending or running, and fewer than `max_failures` consecutive failures.
2. Not before `min_interval_ms` after the last ring was emitted, and not before `owner_quiet_ms` after the last `:acted`. If either hold is in force, it returns `{:wake_at, time}` for when the later one ends.
3. Each room may have at most `max_per_hour` ring starts in any rolling hour. Rooms are tried in order of their oldest unread cursor, lowest first; a room out of budget is skipped. If every room with mail is out of budget, it returns `{:wake_at, time}` for when the first slot frees.
4. Emitting a ring charges that room's budget, sets the interval clock, and makes the ring pending.
5. `{:started, id}` for the pending ring makes it running. `{:refused, id}` for the pending ring clears it and refunds the charge; the interval clock is kept.
6. `{:exited, id, code}` for the pending or running ring clears it. Code 0 resets the failure count. 75 refunds the charge and counts no failure. 76 keeps the charge and counts no failure. Any other code counts one failure.
7. A reply about any other ring id is ignored.
8. `:acted` resets the failure count. It does not refund any charge.
9. While a ring is pending, a snapshot's `running` is ignored: the snapshot may have been sent before the ring arrived. Once a ring is running, a snapshot whose `running` is `nil` clears it with no refund and no failure, and a snapshot naming a different id replaces it. A policy with no ring adopts the id in a snapshot's `running` and rings nothing until that ring exits; an adopted ring has no room to refund.
10. `:offline` forgets the unread mail and the waiters and keeps the budget and failure count. A pending ring is dropped with no refund. A running ring is kept until a snapshot or an exit says otherwise.
